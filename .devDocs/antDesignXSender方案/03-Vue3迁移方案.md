# Vue 3 迁移可行性与实施方案

> 目标：把 ant-design-x Sender 的「词槽模式」迁移到本库（Element-Plus-X，Vue 3 + Element Plus）。产物对齐现有 `Sender` 的 API 风格（`modelValue` / `submit` / ref 方法）。

## 1. 可行性结论

**可行，且与 Vue 组合式 API 天然契合**，但有两条 Vue 特有的硬约束必须正面处理：

| 约束                                        | 说明                                                                                 | 对策                                                                                             |
| ------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Vue 不能响应式管理 contenteditable 内部 DOM | 浏览器直接修改编辑区 DOM，Vue 的 patch 会试图「还原」它 → 丢光标、节点被覆盖、死循环 | 编辑区外壳用 Vue 渲染一次，**内部子节点全部命令式 DOM 操作**，绝不写 `v-for` / `{{ }}`           |
| v-model 受控回写易死循环                    | 输入 → emit → 父组件回写 → watch 重建 DOM → 光标跳动 + 再次 emit                     | watch 回写时**先深度比较**当前序列化结果，一致则跳过重建（对应 ant-design-x issue #1623 的教训） |

其余浏览器层问题（IME、Backspace、粘贴、Selection/Range）与框架无关，ant-design-x 已趟过坑，方案见下文。

## 2. 技术选型对比

| 方案                                                          | 优点                                                      | 缺点                                              | 结论                                               |
| ------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------- |
| A. 自研轻量 contenteditable（ant-design-x 同路线）            | 零新依赖、产物纯文本+结构化、体积小、可控性强             | 键盘/IME/粘贴行为需自研（约几百行）               | **采用**                                           |
| B. Tiptap（`@tiptap/vue-3`）+ atom Node + VueNodeViewRenderer | 光标/选区/删除/撤销栈框架托管，NodeView 直接渲染 Vue 组件 | 引入 ProseMirror 全家桶（体积大），API 心智负担重 | 备选：仅当需求膨胀（协同、可靠撤销、多级块）时启用 |
| C. 在现有 `Sender`（el-input textarea）上魔改                 | 复用现有代码                                              | textarea 无法内嵌元素，无魔改空间                 | 不可行                                             |

决策：**方案 A 独立新组件**，不动现有 `Sender`。与 ant-design-x 双模式哲学一致：纯文本场景继续用 textarea（稳定、IME/撤销栈免费），词槽场景用新组件。

## 3. 数据模型设计

对齐 ant-design-x 的 `slotConfig` 语义，同时保持本库类型风格（`types.d.ts` + `XxxProps` / `XxxEmits`）：

```ts
/** 输入内容分段：纯文本段 或 词槽段 */
export type SlotSegment =
  | { type: 'text'; value: string }
  | {
      type: 'slot';
      /** 唯一标识，序列化/反序列化的映射键 */
      id: string;
      /** chip 上展示的文本 */
      label: string;
      /** 透传给业务/大模型的结构化数据 */
      payload?: Record<string, any>;
    };

export interface XSlotSenderProps {
  modelValue?: SlotSegment[];
  placeholder?: string;
  disabled?: boolean;
  readOnly?: boolean;
  submitType?: 'enter' | 'shiftEnter' | 'cmdOrCtrlEnter' | 'altEnter';
}

export interface XSlotSenderEmits {
  (event: 'update:modelValue', segments: SlotSegment[]): void;
  (event: 'submit', segments: SlotSegment[]): void;
  (event: 'slotRemove', slot: Extract<SlotSegment, { type: 'slot' }>): void;
}
```

ref 实例方法：

```ts
export interface XSlotSenderInstance {
  insertSlot(
    slot: Omit<Extract<SlotSegment, { type: 'slot' }>, 'type'>,
    position?: 'cursor' | 'start' | 'end'
  ): void;
  getValue(): SlotSegment[];
  focus(options?: FocusOptions): void;
  blur(): void;
  clear(): void;
}
```

## 4. 核心实现模式（代码骨架）

### 4.1 职责分离原则

```
Vue（声明式）：只渲染 <div ref contenteditable> 外壳与样式
命令式 DOM  ：内部所有子节点（文本节点 / chip 元素）由 JS 增删
数据映射    ：DOM 上只存 data-slot-id；真实数据存 Map（不把数据塞进 HTML）
序列化      ：遍历 childNodes → Segment[]
```

### 4.2 关键实现点

```ts
// —— chip（原子块）——
function createChip(seg: SlotSegment & { type: 'slot' }): HTMLElement {
  slotMap.set(seg.id, seg);
  const chip = document.createElement('span');
  chip.className = 'elx-slot-chip';
  chip.contentEditable = 'false'; // 关键：光标整体跳过，不可编辑内部
  chip.dataset.slotId = seg.id;
  chip.textContent = seg.label;
  return chip;
}

// —— 插入到光标处 ——
function insertSlot(seg, position = 'cursor') {
  editor.focus();
  const chip = createChip({
    type: 'slot',
    id: seg.id ?? crypto.randomUUID(),
    ...seg
  });
  // ... Range API 定位插入（省略，同 ant-design-x）
  const tail = document.createTextNode('\u200B'); // 零宽空格：给光标落脚
  chip.after(tail);
  // ... reset selection
  emitChange();
}

// —— 序列化：DOM → 数据 ——
function serialize(): SlotSegment[] {
  const segs: SlotSegment[] = [];
  editor.childNodes.forEach(node => {
    if (node.nodeType === Node.TEXT_NODE) {
      const value = (node.textContent ?? '').replace(/\u200B/g, '');
      if (value) segs.push({ type: 'text', value });
    } else {
      const id = (node as HTMLElement).dataset.slotId;
      if (id && slotMap.has(id)) segs.push({ ...slotMap.get(id)! });
    }
  });
  return segs;
}

// —— 受控回显（防死循环，对应 issue #1623）——
watch(
  () => props.modelValue,
  val => {
    if (JSON.stringify(val ?? []) !== JSON.stringify(serialize())) {
      renderFromModel(val ?? []); // 仅外部真实变更时重建 DOM
    }
  }
);
```

### 4.3 必须自研的浏览器行为清单

| 行为               | 处理方式                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| Backspace 删词槽   | 选区折叠且 offset=0 时，检查前一兄弟是否 chip → `preventDefault()` 整体删除（含 Map 清理、emit slotRemove） |
| 剪切词槽           | 复用退格逻辑（PR #1537 教训）                                                                               |
| 粘贴               | `preventDefault` + `insertText`，只进纯文本，防 HTML 注入                                                   |
| IME 中文输入       | `compositionstart/end` 期间不 emit；`compositionend` 后再序列化                                             |
| placeholder        | 用 `:empty::before` 伪元素，不用真实占位节点（防光标高度突变）                                              |
| chip 内嵌 Vue 组件 | 命令式挂载：`render(h(ChipComp, props), host)`；删除 chip 时 `render(null, host)` 卸载，防内存泄漏          |
| chip 事件          | 在编辑区根节点事件委托（`@click` 读 `dataset.slotId`），不为每个 chip 绑定 Vue 监听                         |

## 6. 分阶段实施计划

> 进度勾选统一维护在 [README.md](./README.md) 的「进度跟踪」章节。

1. **POC（先证明核心风险可控）**：独立最小实现，验证四件事——插入/删除/序列化/受控回显不抖动，IME 正常。
2. **组件实现**：按第 3、4 节设计落地，补齐 ref 方法与样式（对齐 Element Plus CSS 变量）。
3. **文档与 Demo**：中文文档 + 4 个核心 demo（基础用法 / 受控回显 / 词槽填充 / @技能）。
4. **质量保障**：单测（序列化、退格、粘贴净化）、三浏览器验证、`vue-tsc` 通过、changeset。

## 7. 验收标准

- [ ] 输入文本 + 插入词槽，`update:modelValue` 输出正确的 `SlotSegment[]`（文本段/词槽段顺序与界面一致）
- [ ] 中文输入法连续输入不丢字、不重复 emit
- [ ] 受控模式外部回写不抖动、不丢光标（模拟 issue #1623 场景）
- [ ] Backspace / 剪切删除词槽是整体删除，且 `slotMap` 同步清理
- [ ] 粘贴富文本被净化为纯文本
- [ ] `vue-tsc` 与构建通过，现有组件零回归
