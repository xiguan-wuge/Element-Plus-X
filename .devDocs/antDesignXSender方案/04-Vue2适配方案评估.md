# Vue 2 适配方案评估

> 结论先行：**核心编辑引擎可直接复用，框架适配层需要重做**。这套方案的主体（hooks + 序列化）是刻意做成框架无关的，这是移植可行性的关键。若确有 Vue 2 需求，推荐「抽 core 纯 JS 包 + 两端薄适配层」的路径。

## 一、分层可用性评估

| 层            | 涉及文件                               | Vue 2 可用性 | 说明                                                              |
| ------------- | -------------------------------------- | ------------ | ----------------------------------------------------------------- |
| 光标/选区引擎 | `hooks/use-cursor.ts`                  | ✅ 直接复用  | 纯 Range/Selection DOM API，零框架依赖                            |
| 节点构建器    | `hooks/use-slot-builder.ts`            | ✅ 直接复用  | 纯 `document.createElement` + dataset，零框架依赖                 |
| 序列化逻辑    | `SlotTextArea.vue` 内 `getEditorValue` | ✅ 直接复用  | 遍历 `childNodes` + dataset 反查配置，纯 DOM                      |
| 状态管理      | `hooks/use-slot-config-state.ts`       | ⚠️ 需适配    | Vue 2 响应式基于 `Object.defineProperty`，无法侦测属性增删        |
| 词槽 UI 渲染  | `SlotTextArea.vue` 的 Teleport 部分    | ❌ 需重做    | `Teleport` 是 Vue 3 特性，Vue 2 无对等内建能力                    |
| 组件外壳      | `index.vue` / `SkillTag.vue`           | ❌ 需重写    | `<script setup>`、`defineExpose`、`defineEmits` 等均为 Vue 3 特性 |
| UI 组件库     | Element Plus                           | ❌ 需替换    | Element Plus 仅支持 Vue 3，Vue 2 对应 Element UI                  |

复用比例估算（按代码行数）：

- **Vue 2.7**：约 60% 直接复用（三个 hooks + 序列化 + 样式），改造集中在 Teleport 替换与组件外壳重写
- **Vue 2.6 及以下**：约 40%，hooks 需从 Composition API 改写为 mixin/插件函数形式

## 二、三个关键适配点

### 2.1 响应式差异（小改）

`slotValues` 的动态增删在 Vue 2 会失去响应性，这是 `Object.defineProperty` 的固有限制：

```js
// ===== Vue 3 写法（现方案，use-slot-config-state.ts）=====
delete slotValues[key]; // Proxy 可侦测
Object.assign(slotValues, newValues); // 新增属性可侦测

// ===== Vue 2 适配 =====
Vue.delete(slotValues, key); // 或 this.$delete
Vue.set(slotValues, key, value); // 新增属性必须走 Vue.set
```

逐处替换要点：

| 现方案位置                                 | Vue 3 写法                             | Vue 2 替换                             |
| ------------------------------------------ | -------------------------------------- | -------------------------------------- |
| `syncFromProps` 删除无效 key               | `delete slotValues[key]`               | `Vue.delete(slotValues, key)`          |
| `syncFromProps` / `mergeSlotConfig` 合并值 | `Object.assign(slotValues, newValues)` | 循环 `Vue.set(slotValues, key, val)`   |
| `removeSlot` 删除值                        | `delete slotValues[key]`               | `Vue.delete(slotValues, key)`          |
| `slotConfigMap`（非响应式 Map）            | 原样保留                               | 原样保留（纯命令式读取，无响应式诉求） |

注意：`slotConfigMap` 刻意设计为**非响应式** Map，这层在 Vue 2 下无需任何改动——它是给序列化/键盘处理命令式读取的，不进渲染依赖。

### 2.2 词槽 UI 渲染（主要工作量）

现方案（Vue 3）：命令式创建宿主 span → `Teleport` 把 `el-input` / `el-dropdown` / custom VNode 渲染进去。

Vue 2 没有内建 Teleport，两条替代路线：

**路线 A：手动实例挂载（推荐）**

与 ant React 版 `createPortal` 精神一致，直接把 Vue 实例挂到宿主 span：

```js
// 挂载（以 input 词槽为例）
import Vue from 'vue';
import ElInput from 'element-ui/lib/input';

function mountSlotComponent(slotSpan, config, ctx) {
  const vm = new Vue({
    el: slotSpan, // 直接挂到命令式创建的宿主 span
    parent: ctx.parentVm, // 挂到 Sender 实例下，继承全局注册的 Element UI 组件
    data: {
      value: ctx.slotValues[config.key]
    },
    render(h) {
      return h(ElInput, {
        props: { value: this.value, size: 'mini' },
        on: {
          input: v => {
            this.value = v;
            ctx.updateSlot(config.key, v); // 回写主状态
          }
        }
      });
    }
  });
  return vm;
}

// 卸载（clear / removeSlot 时必须调用，防止内存泄漏）
function unmountSlotComponent(vm) {
  vm.$destroy();
  vm.$el?.remove();
}
```

要点与坑：

1. **生命周期必须手动管理**：`clear()` / `removeSlot()` / `initClear()` 中先 `$destroy` 再清 DOM，否则实例泄漏。现方案 `slotTeleportHosts.clear()` 的位置对应替换为「遍历 vm 缓存 Map 逐个 `$destroy`」
2. **`parent` 挂到主实例**：让子实例继承全局注册的 Element UI 组件与 `$createElement`，避免重复注册
3. **key 缓存结构**：`slotTeleportHosts: Map<string, HTMLElement>` 替换为 `slotVmCache: Map<string, Vue实例>`，Teleport 模板区块整体删除
4. **custom 词槽 customRender**：Vue 2 下 `customRender` 的入参 `h` 从闭包取（主实例的 `$createElement`），返回 VNode 后用 `new Vue({ render: () => vnode })` 挂载，或让用户直接返回组件选项对象

**路线 B：portal-vue 库**

API 与 Teleport 类似（`portal-target`），但宿主是命令式创建的 DOM 时，需要动态注册 target，管理成本高于路线 A。仅在词槽宿主本身也是声明式渲染的场景下才划算，本项目不适用。

结论：**选路线 A**。ant-design-x 原版用的 `createPortal` 就是手动挂载思想，Vue 2 手动实例挂载是对等翻译。

### 2.3 UI 库 API（机械替换）

Element Plus → Element UI 的属性/事件差异，属于体力活，逐处对照替换：

| 现方案（Element Plus）                            | Vue 2 版（Element UI）                                                         |
| ------------------------------------------------- | ------------------------------------------------------------------------------ |
| `el-input` `:model-value` + `@update:model-value` | `v-model`                                                                      |
| `el-input` `:validate-event="false"`              | 同名支持，保留                                                                 |
| `el-dropdown` `@command`                          | 同名支持，保留                                                                 |
| `el-dropdown-item` `:command`                     | 同名支持，保留                                                                 |
| `el-tooltip` `:show-after="100"`                  | `:open-delay="100"`                                                            |
| `el-switch` 尺寸 `size="small"`                   | `size="mini"`                                                                  |
| 图标组件 `@element-plus/icons-vue`                | `element-ui/lib/icon`（仅 class 图标，SkillTag 关闭按钮改为字符 × 或自备 SVG） |
| popper 类名 `popper-class`                        | 同名支持，保留                                                                 |

## 三、版本边界：2.7 与 2.6 的差异

| 能力                                                   | Vue 2.7                                  | Vue 2.6 及以下                           |
| ------------------------------------------------------ | ---------------------------------------- | ---------------------------------------- |
| Composition API（`ref`/`reactive`/`computed`/`watch`） | ✅ 内建                                  | ❌ 无                                    |
| `Vue.observable`                                       | ✅                                       | ✅                                       |
| `shallowReactive`                                      | ✅                                       | ❌ 需用 `Object.freeze` 变通或放弃浅响应 |
| `<script setup>`                                       | ✅（编译器支持）                         | ❌ 需改 Options API                      |
| hooks 迁移成本                                         | 几乎原样迁移（仅 `Vue.set/delete` 差异） | 需改写为 mixin 或工厂函数                |

**Vue 2.7**：三个 hooks 中的 `reactive` / `shallowReactive` 均内建支持，基本原样复制 + 2.1 节的 `Vue.set/delete` 替换即可。组件外壳可用 `<script setup>`（2.7 支持），`defineExpose` 换成 Options API 的 `methods` + 实例方法天然暴露。

**Vue 2.6**：没有 Composition API，`useSlotConfigState` 等需改写为 mixin 或纯工厂函数（返回普通对象 + 手动 `Vue.observable` 包裹）。`SlotTextArea` 需整体改 Options API + `render` 函数。成本明显更高，除非存量项目强依赖，不建议投入。

## 四、推荐落地路径

```
packages/
├── slot-core/               # 新抽：纯 JS，零框架依赖
│   ├── use-cursor.js        # 光标/选区（从 Vue 3 版原样抽出）
│   ├── use-slot-builder.js  # 节点构建（原样抽出）
│   ├── serialize.js         # getEditorValue / getNodeTextValue 抽离
│   └── types.d.ts
├── core/（现有 Vue 3 包）    # 薄适配层：reactive 状态 + Teleport 渲染
└── core-vue2/（可选新增）    # 薄适配层：Vue.set/delete + 手动实例挂载
```

分阶段：

1. **阶段一（重构，无行为变化）**：从 `SlotTextArea.vue` 中把 `getEditorValue` / `getNodeTextValue` 抽到 `slot-core/serialize.js`，Vue 3 版改为引用，跑通现有验证
2. **阶段二（Vue 2.7 适配包）**：`slotVmCache` 替换 Teleport 区块、`Vue.set/delete` 替换、Element UI 替换
3. **阶段三（可选，Vue 2.6）**：仅在有明确存量需求时再做

## 五、风险与注意项

| 风险                      | 说明                                               | 缓解                                                                                                  |
| ------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Vue 2 已 EOL              | 2023-12-31 停止维护，无安全补丁                    | 新项目不建议；存量项目按需评估                                                                        |
| 手动挂载的内存泄漏        | `$destroy` 忘调会累积泄漏                          | 封装统一的 mount/unmount 管理器，clear/removeSlot/组件卸载钩子统一走 unmount                          |
| Vue 2 响应式数组/对象陷阱 | `Vue.set/delete` 漏用导致视图不更新                | slotValues 的所有写操作收敛到 `useSlotConfigState` 内部，禁止外部直改                                 |
| Element UI 图标体系差异   | 无 SVG 组件图标                                    | SkillTag 关闭按钮内置 SVG 或字符 ×                                                                    |
| IME 组合输入              | Vue 2 下 `v-model` 与 contenteditable 原生行为叠加 | 本方案 contenteditable 不走 v-model，命令式监听 `compositionstart/end`，与 Vue 3 版一致，理论无新风险 |
| 多实例并存                | 手动挂载实例的 `parent` 指向错乱                   | 统一以 `SlotTextArea` 实例为 parent                                                                   |

## 六、结论

| 场景         | 建议                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- |
| 核心编辑引擎 | 抽成框架无关的 `slot-core` 纯 JS 包，一套代码双端复用（ant 的 DOM 操作与 React 解耦设计带来的红利） |
| Vue 2.7      | 值得做，约 60% 复用，主要工作在 Teleport → 手动实例挂载 + Element UI 替换                           |
| Vue 2.6      | 除非存量项目强依赖，不建议投入                                                                      |
| 新项目       | 直接用 Vue 3 版；Vue 2 仅作为存量兼容手段                                                           |
